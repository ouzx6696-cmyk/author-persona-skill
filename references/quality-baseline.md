# 报告质量基准（Quality Baseline）

本文件是产出验收的参照系，提炼自高质量解构报告的共性标准：诊断深度、失效边界、跨期证据、置信分级与量化禁令。分析提示词已内嵌其精简版；本文供人工对照打分。

## 1. 综合诊断因果链（定量层每小节的写法）

每个 1.x 小节 = **命名型总起句 + 因果诊断段**：

- 结构：数值并列 → 共振/矛盾指认 → 机制命名 → 阅读效果；
- 长度 120–250 字，禁止纯数值罗列或一句话带过；
- 总起句必须"命名"一个风格命题，而不是复述指标名。

达标示例（合成样本 A）：
> 平均句长39字 + 长句占比26% + 逗号句号比3.4:1，三者共振指向一个核心特征——铺陈式长句叙事。
> 感叹号0.6/千字 vs 问号4.7/千字，这一组对比是该样本最鲜明的矛盾信号。

不达标反例：`平均句长25.6字，短句率31.6%。`（只有数值，无机制、无因果、无命名）

## 2. 失效边界三要素（技法卡 boundary 字段）

boundary 必须包含：**禁用场景 + 退化成因 + 规避动作**。

达标示例（合成样本 B）：
> 若每次都以"早有准备"收场，读者会免疫；需保留若干次准备不足来维持真实感。
> 若回收间隔过长且中途无任何再提示，读者会遗忘，惊喜变突兀；需要"轻提"维持记忆温度。

不达标反例：`打斗场景慎用。`（只有场景，无成因、无规避动作）

## 3. 跨期证据标注

证据锚点必须写明所属时期（开头 (Begin)/发展 (Develop)/成熟 (Mature)/演变 (Evolve)/结尾 (Ending)，或百分比区间），证明该技法是全书稳定特征而非局部现象。至少一张技法卡引用两个不同时期的证据。

达标示例（合成样本 B）：`开头即建立（陌生环境适应章）；中段群体场景出现多重误读；后期旧识逐步产生怀疑。`

## 4. 置信分级

- 数值层标注数据源可靠性：直接（可精确测量）/ 启发式（分类统计）/ 弱信号（词汇语域）；
- 结论层使用 高 / 中 / 待确认 三档，并说明哪些属于解释层推断。

## 5. 量化禁令三元组（作家分身提示词）

每条禁令必须是 **指标 + 数值 + 单位** 的可直接执行三元组，且能回溯到定量层实测值。

达标示例（合成样本 C）：
- `省略号：0.0/千字，严禁使用`
- `感叹号每千字不超过1个，情绪高潮也不用感叹号`
- `平均句长：35–38字（中位37字）`
- `心理描写占比不得超过35%`

## 6. 合成示范四件套（作家分身提示词）

最高档示范 = **正确示范 + 错误示范 + 错误点标注 + 数值自校验**：

- 示范文本必须现场合成（通用角色），禁止摘录原文；
- 错误示范逐条标注违规点；
- 示范末尾附一行数值自校验，回扣铁律区间（如"平均句长约38字，符合35–42字区间；省略号0、破折号0"）。

## 7. 脱敏红线

报告正文（证据引文行除外）不得出现：作者名、作品名、真实角色名、地名/功法名等原专名。原型标签用 2–4 字中性词（如"主角型/谋臣型/圣山地标"）。脱敏映射只覆盖候选池实际给出的条目（作者/作品 2 项 + 高频说话人 3 项 + 书名号术语 5 项，通常 ≤10 项），禁止自行发明更多映射。

## 8. 第〇部分质量线

- `writer_contract` 四字段（positioning / purpose / style_marks_synthesis / enemy_clauses）非空（≥5 字）或显式写「报告未提供」，禁止编造；enemy_clauses 2–4 条。
- `style_marks_synthesis` 必须由 1.11 风格标记综合提炼成一句整体风格命题，而非罗列重复；无法覆盖的标记应在命题中说明取舍。
- 每张技法卡的 `serves_purpose` 写可判断的读者效果并回指第〇部分条款；✅「让多轮交锋的对白紧凑连贯」；❌「提升文笔 / 增强可读性」（空泛词，无法判断是否兑现）。
- 第〇部分受材料边界铁律约束：只能从本次语料的定量数据与证据合成，禁止调用模型记忆。

## 9. 运行时质量自评（代码闸门，非阻断）

`finalize_analysis` 在四重校验之外另跑一次质量自评（`report/quality.py`），结果写入 `validation.quality`；阈值与本文同源，人读基准与机器判定不会各说各话：

| 信号 | 判定口径 | 阈值 |
|---|---|---|
| 1.x 小节篇幅 | `full` / `partial` / `low` | ≥120 字满分；≥60 字为 partial |
| 定性小节 1.9–1.11 | 机制诊断字数 | <80 字计入 `quality.reasons` |
| 风格标记数据支撑率 | 1.11 中带数值或占位符的行占比 | <50% 且总行数 ≥3 计入 reasons |
| 长线布局锚点 | `long_arc` 中 `[cXXX]` 锚点覆盖的时期数 | 不足 2 组计入 reasons |

判定结果：`quality_status` 为 `passed` / `failed`，并汇总为 `publishable`。**自评不阻断**——它不改 `validation.status`，只回答"契约合规的这份报告够不够深"。`quality.notes` 承载 partial 小节这类提示性观察，与阻断性的 `errors` 分层；出现「`status: passed` 而 `publishable: failed`」时是否返工由调用方决定。
